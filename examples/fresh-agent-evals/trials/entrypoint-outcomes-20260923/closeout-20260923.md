## Completed entry trials — original verdicts retained

### `discovery-quickstart-entry-luna-rerun`

- [Original trial record](discovery-quickstart-entry-luna-rerun.trial.json)
- [Original, unregraded verdict](discovery-quickstart-entry-luna-rerun.trial.verdict.json)
- [Substantive artifact](artifacts/discovery-quickstart-entry-luna-rerun/quickstart-research.json)
- Recorded original verdict: **FAILED, 6 failures**.

Two failure reasons came from treating effective permission keys as event-tool
names: the profile correctly admitted OpenCode `edit`, while the completed
native artifact action was normalized as `apply_patch`; the artifact-write set
only recognized `edit`. Four further messages duplicated two exact-schema
mismatches: the artifact's source and algorithm descriptions were
substantively accurate (including `genetic (GA)`), but the corresponding
fields must equal the selected record's exact canonical URL and exact algorithm
identifier. The task prompt did not make that copy contract clear.

The corrected evaluator keeps permission keys separate from normalized file
action names and recognizes only `edit`, `write`, and `apply_patch` for the
documented `edit` permission. It still requires native completion, raw call-ID
corroboration, matching command digests, and a confined artifact path. The
prompt now says to copy the exact canonical URL and algorithm identifier from
discovered records; machine-readable matching remains exact. These changes
correct the evaluator contract and do **not** regrade or convert this original
trial verdict into a pass.

### `discovery-pasted-entry-luna`

- [Original trial record](discovery-pasted-entry-luna.trial.json)
- [Original, unregraded verdict](discovery-pasted-entry-luna.trial.verdict.json)
- [Substantive artifact](artifacts/discovery-pasted-entry-luna/pasted-entry-contribution.json)
- Recorded original verdict: **FAILED, 5 failures**.

Two failures were the same `apply_patch` event-label mismatch. One is a genuine
isolation failure: action 21 attempted to read a hallucinated sibling path and
received a native error. That failure remains valid and strict path confinement
is unchanged. The other two failures were rubric assumptions: the artifact
selected `docs/agents/references/onboarding.json`, a canonical documentation
source, but the old target check allowed only Markdown; and its live-boundary
text had explicit user authorization, an independently started same-harness
CLI with a distinct session identity, and no main-session fallback, but the old
check demanded a literal `README` token.

The corrected rubric admits that one canonical onboarding JSON source only
when it exists in the workspace, is confined, actually read, and cited; other
JSON files remain disallowed as targets. The live-boundary check requires the
authorization, same-harness identity, and no-fallback semantics without a
literal README requirement. These changes do **not** erase the real external
read attempt, alter the artifact, or regrade the original verdict.
